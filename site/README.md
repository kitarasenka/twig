# Сайт 🌱 Twig

Статический лендинг на русском языке. Без сервера приложения, внешних шрифтов, аналитики и дополнительных зависимостей.
Небольшой локальный `site.js` переключает примеры и включает конечные анимации.
Без JavaScript все три примера видны подряд; навигация и скачивание работают.
Оригинальная иконка 🌱 Twig, палитра и Fira Sans взяты из приложения.

## Сборка и просмотр

Из `modules/git_desk`, после обычного `npm ci` (Node 20.19+ в ветке Node 20):

```sh
npm run build:site
npm run preview:site
```

Открыть `http://127.0.0.1:5190`. Предпросмотр обслуживает только `site/dist/`
на локальном интерфейсе. Это инструмент разработки, не сервер для публикации.
Изменили исходники — снова выполните `npm run build:site` и обновите страницу.

`site/index.html` — текст и структура; `site/style.css` — адаптивная вёрстка.
`site/site.js` — доступные с клавиатуры вкладки и появление секций при прокрутке.
`site/build.mjs` подставляет версию и ссылки, копирует локальные ресурсы.
Результат в `site/dist/` игнорируется Git и не входит в Electron-приложение.

По умолчанию кнопки скачивания указывают на соседний каталог `downloads/`
(самостоятельный хостинг). Переменная окружения `TWIG_SITE_DOWNLOAD_BASE` —
абсолютный `https://`-префикс — переносит ссылки на внешнее хранилище, например
на ассеты GitHub Release: сборка приписывает к нему имена файлов из
`downloads.json`. Значение проверяется на схему; на не-`https` или подозрительный
путь сборка падает.

## Установщики

```sh
npm run pack:mac
npm run pack:win
npm run pack:linux
```

Запускайте соответствующую команду на целевой ОС. Команда сначала собирает
приложение, затем запускает установленный electron-builder без публикации.
Для первого запуска упаковщика могут понадобиться сетевые загрузки его
платформенных инструментов. Итоговые файлы появляются в `release/`:

| Платформа | Имя файла (`VERSION` берётся из package.json) |
| --- | --- |
| macOS Apple Silicon | `Twig-VERSION-macos-arm64.dmg` |
| macOS Intel | `Twig-VERSION-macos-x64.dmg` |
| macOS Apple Silicon, портативный | `Twig-VERSION-macos-arm64.zip` |
| macOS Intel, портативный | `Twig-VERSION-macos-x64.zip` |
| Windows x64 | `Twig-VERSION-windows-x64.exe` |
| Windows x64, портативный | `Twig-VERSION-windows-x64-portable.exe` |
| Linux x64 | `Twig-VERSION-linux-x86_64.AppImage` |
| Debian / Ubuntu x64 | `Twig-VERSION-linux-amd64.deb` |

Портативные сборки (`.zip` для macOS, `-portable.exe` для Windows, а также
`.AppImage` для Linux) запускаются без установки. По умолчанию настройки и
демо-песочница хранятся в стандартном пользовательском каталоге ОС. Автономный
режим: `TWIG_DATA_DIR=<абсолютный путь>` в окружении, либо пустой файл-маркер
`.twig-portable` рядом с приложением (Windows-portable включает его сам) —
тогда весь `userData` уезжает в папку `twig-data` рядом с бинарём.
Логика — `main/portable.js`, проверка — `scripts/checks/portable.mjs`.

Источник имён и архитектур один: `build.mac/win/linux` в `package.json`.
Сайт читает те же `artifactName` и `target`, которые использует упаковщик.
Нет отдельно зашитой версии или независимых имён ссылок.
Сборка сайта выводит точные ожидаемые имена и записывает `downloads.json`.
При добавлении нового типа установщика обновите таблицу расширений в `build.mjs`.

Упаковка и запуск всех нативных установщиков не проверены в рамках лендинга.
Проверена схема конфигурации установленного electron-builder. Подписание и
нотариальное заверение не настроены; страница объясняет предупреждения ОС.

## Размещение на сервере

1. Собрать установщики выбранной версии на соответствующих ОС.
2. Выполнить `npm run build:site` из исходников **той же версии**.
3. Скопировать содержимое `site/dist/` в каталог сайта на сервере.
4. Создать там `downloads/` и положить все сборки из `release/`
   с исходными именами из `downloads.json`. Другие файлы упаковщика не нужны.
5. Проверить скачивание каждой сборки перед открытием сайта посетителям.

```text
каталог-сайта/
  index.html
  style.css
  site.js
  tokens.css
  downloads.json
  assets/
  downloads/
    Twig-VERSION-macos-arm64.dmg
    Twig-VERSION-macos-x64.dmg
    Twig-VERSION-macos-arm64.zip
    Twig-VERSION-macos-x64.zip
    Twig-VERSION-windows-x64.exe
    Twig-VERSION-windows-x64-portable.exe
    Twig-VERSION-linux-x86_64.AppImage
    Twig-VERSION-linux-amd64.deb
```

Ссылки относительные: сайт работает и в корне домена, и в подкаталоге.
Сервер должен отдавать установщики как файлы, а отсутствующий установщик —
с HTTP 404, без подмены на `index.html`. До загрузки бинарных файлов кнопки
указывают на ожидаемые пути и будут возвращать 404. Здесь нет автоматического
деплоя, загрузки установщиков или интеграции с nodex/PM2.

## GitHub Pages

GitHub Pages для приватного репозитория требует плана Enterprise, поэтому Twig
живёт в отдельном **публичном** репозитории (см. `MIGRATION.md`), а не в
приватном монорепозитории `nodes-managers`.

В публичном репозитории воркфлоу `.github/workflows/site.yml` собирает и
публикует лендинг на GitHub Pages при push в `main`, затрагивающем `site/**`,
`package.json` или `renderer/src/ui/tokens.css`, а также вручную
(`workflow_dispatch`). Он ставит только продовые зависимости
(`npm ci --omit=dev`, без Electron), запускает `build:site` с
`TWIG_SITE_DOWNLOAD_BASE`, указывающим на `releases/download/twig-v<version>/`
этого же репозитория (`${{ github.repository }}`), и деплоит `site/dist/`
через `actions/deploy-pages`.

Один раз в настройках репозитория: **Settings → Pages → Build and deployment →
Source: GitHub Actions**.

Установщики на Pages не кладутся — лимит около 1 ГБ на сайт, восемь сборок
Electron больше. Порядок выпуска версии:

1. Собрать установщики на трёх ОС (`pack:mac` / `pack:win` / `pack:linux`).
2. Создать GitHub Release с тегом `twig-v<version>` (та же версия, что в
   `package.json`) и приложить все восемь файлов из `release/` с исходными
   именами из `downloads.json`.
3. Слить изменение версии в `main` — воркфлоу пересоберёт сайт, и кнопки
   начнут указывать на ассеты этого Release.

Пока Release с нужным тегом не опубликован, кнопки возвращают 404 — то же
поведение, что при самостоятельном хостинге до загрузки файлов.

Самостоятельный хостинг (без GitHub Pages) по-прежнему возможен: без
`TWIG_SITE_DOWNLOAD_BASE` кнопки указывают на соседний `downloads/`, см. раздел
«Размещение на сервере» выше.

## Проверка

При работающем `npm run preview:site`:

```sh
node site/check.mjs
```

Нужен Chromium для установленного Playwright. Можно задать путь к уже
установленному браузеру через `TWIG_BROWSER_PATH`. Проверка проходит размеры
375, 768, 1024 и 1440 px с отключённым JavaScript: отсутствие переполнения,
ресурсы, навигация, клавиатура, раскрытие инструкции и имена восьми скачиваний. Дополнительно проверяются
вкладки с включённым JS на локальном `site/dist/index.html`, управление
стрелками/Home/End, отсутствие скачков
высоты примеров и переключение reduced motion.
Ответы установщиков подменяются тестовыми данными: это проверка ссылок,
не работоспособности бинарников. Снимки — `artifacts/site-*.png`.

## Визуальные материалы и утверждения

- `assets/twig.png` — копия `build/icon.png`, уменьшенная до 512×512:
  `sips -z 512 512 build/icon.png --out site/assets/twig.png`. Не перерисована.
- `assets/workspace.png` — снимок демо-вкладки приложения из
  `artifacts/sandbox-dark.png`; подпись на сайте явно указывает демо-репозиторий.
  Копия хранится в Git, сборка не зависит от игнорируемых `artifacts/`.
- Маленькая иконка и локальные шрифты копируются при сборке; лицензия шрифта
  включена в `assets/FONT-LICENSE.txt`.
- Цифра 100 000 убрана из лендинга: тест алгоритма раскладки не показывает
  скорость работы всего приложения.
- 128 → примерно 7 проверок — иллюстрация деления диапазона пополам,
  с указанными условиями. BugHunter требует ручной проверки версий.
- Нет обещаний облачной синхронизации марок, автоматического исправления
  багов или функций, которых нет в клиенте.

Решения ui-ux-pro-max: крупная типографика, одна основная цель — скачивание,
адаптивная сетка, контрастные фокусы, элементы управления от 44 px,
`prefers-reduced-motion`. Сохранены палитра приложения и Fira Sans вместо
предложенных скиллом другой палитры и Space Mono. Чистый HTML/CSS подходит
статической странице; Tailwind и React в сайт не добавлены.

Исследование конкурентов и основания утверждений: [COMPETITORS.md](COMPETITORS.md).
Короткие анимации не повторяются автоматически; reduced motion отключает их.
Шрифты, цвета и оформление приложения сохранены. Первый экран показывает
сценарии работы; большой логотип и декоративные лозунги убраны.

После обновления `site/preview.mjs` перезапустите уже работающий preview: старый
процесс не перечитывает таблицу MIME и отдаёт `.js` как octet-stream. Checker
сообщает об этом отдельно; интерактивную сборку также можно открыть напрямую
как `site/dist/index.html` (без сервера).
