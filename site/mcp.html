ПОЧЕМУ ЭТО КРУТО

Не обёртка над git,
а смысловой API к репозиторию.

Агент может запустить git diff и сам. Но тогда он читает всё подряд, гадает, что важно, и не знает, на что вы смотрите.

01 / СТРУКТУРА ВМЕСТО ТЕКСТА

Ответ, который не надо разбирать

Статусы словами, счётчики строк по файлу, ханки с диапазонами и id, ветка с upstream и расхождением, идущий merge или rebase. Агент сразу работает с данными, а не парсит человеческий вывод.

02 / ОТ СВОДКИ К СТРОКЕ

Ровно столько, сколько спросили

Сначала сводка в несколько сотен байт, потом список файлов, потом дифф одного файла, потом один ханк. Огромный дифф приходит оглавлением: ханки с id, текст — по запросу. Контекст агента не тонет в чужих файлах.

03 / ЧТО ВЫДЕЛЕНО У ВАС

«Объясни этот коммит» — без хэша

Агент видит, какой коммит, диапазон сравнения или файл открыт в 🌱 Twig. Выделили строку в графе — спросили агента. Копировать хэш и путь больше не нужно.

04 / ТОЛЬКО ЧТЕНИЕ

Агент предлагает, решаете вы

Нет инструментов commit, stage, checkout, reset, push и нет запуска команд. План коммитов агент предлагает, а выполняете его вы — в 🌱 Twig, где staging построчный и почти каждое действие можно отменить.

05 / ВСЁ НА ВИДУ

Каждая команда агента — в журнале

Любая команда Git, которую вызвал агент, попадает в консоль 🌱 Twig с плашкой MCP: argv, каталог, вывод, код. Ваши действия во вкладке «My» не смешиваются с чтениями агента.

06 / ЛЮБОЙ КЛИЕНТ

Стандартный MCP, без облака

Обычный Model Context Protocol поверх stdio: никаких SDK провайдеров, аккаунтов и серверов. Мост запускается на исполняемом файле самого 🌱 Twig — отдельный Node.js не нужен.

СВОДКА → ФАЙЛ → ХАНК

Четыре шага
вместо одного огромного вывода.

Настоящие ответы 🌱 Twig на демо-песочнице, сокращённые для читаемости. Справа от названия — размер полного ответа.

  1. 1
    get_workspace_context434 Б

    Ветка, upstream, расхождение, идущая операция и счётчики файлов. Без диффов.

    {"branch": {
  "name": "main",
  "upstream": "origin/main",
  "ahead": 1, "behind": 0 },
 "operation": null,
 "workingTree": {
  "clean": false,
  "staged": 0, "unstaged": 1,
  "untracked": 1 }}
  2. 2
    list_changes311 Б

    Каждый файл со статусом, стороной индекса и числом строк. Постранично.

    {"total": 2, "files": [
 {"path": "README.md",
  "status": "modified",
  "staged": false,
  "insertions": 1,
  "deletions": 0},
 {"path": "notes.todo",
  "status": "untracked"}]}
  3. 3
    get_diff614 Б

    Дифф одного файла, разбитый на ханки с id и диапазонами строк.

    {"path": "README.md",
 "side": "unstaged",
 "hunks": [{
  "id": "w3-77f252e1d76e",
  "oldStart": 6,
  "newStart": 6,
  "added": 1,
  "patch": "@@ -6,3 +6,4 @@…"}],
 "truncated": false}
  4. 4
    get_diff_hunk1 ханк

    Один ханк. Если файл с тех пор изменился, ответ — INVALID_HUNK, а не соседний ханк.

    {"hunk": {
  "id": "w3-77f252e1d76e",
  "patch": "…
 Keep the details close…
+One unstaged edit.\n",
  "truncated": false}}

Большой дифф не съедает контекст

Файл на 300 ханков приходит оглавлением: пока хватает бюджета — с текстом, дальше — с id и patch: null. Агент открывает только нужные ханки. JSON никогда не обрезается на середине, а у обрезанного ответа всегда есть truncated и подсказка, что запросить дальше.

9 ИНСТРУМЕНТОВ · ВСЕ ТОЛЬКО ЧИТАЮТ

Небольшие инструменты
вместо get_everything.

Каждый принимает необязательный repository — имя, корень или любой путь внутри. Агент может передать свою рабочую папку.

get_workspace_context

Сводка: ветка, upstream, операция, счётчики файлов, выделенное в окне.

list_repositories

Подключённые репозитории и тот, что открыт в 🌱 Twig.

list_changes

Изменённые файлы без диффов: статус, staged, строки +/−. Постранично.

get_diff

Дифф одного файла по ханкам; staged или нет; новый файл — как добавление.

get_diff_hunk

Один ханк по id, с проверкой, что файл не изменился.

get_history

Компактный список коммитов HEAD, ветки, тега или всех веток сразу.

get_commit

Сообщение, автор, родители и файлы со счётчиками строк. Без патча.

get_commit_diff

Патч коммита: целиком для маленького, по файлу или по ханку для большого.

get_ui_context

Что открыто в окне: вид, коммит, диапазон, файл. Чего 🌱 Twig не хранит — null.

СЦЕНАРИИ

Что спросить
у агента.

Под каждой просьбой — инструменты, которые агенту хватит вызвать.

01 / КОММИТЫ

«Разбей мои изменения на коммиты»

Агент смотрит сводку и список файлов, читает дифф только нужных файлов и предлагает группы с сообщениями. Застейджить можно построчно в 🌱 Twig.

workspace → list_changes → get_diff

02 / РЕВЬЮ

«Проверь, что я застейджил»

Только индекс, файл за файлом — то, что действительно уйдёт в коммит, а не всё рабочее дерево.

list_changes → get_diff staged

03 / ОБЪЯСНЕНИЕ

«Объясни коммит, который я выделил»

Агент узнаёт выделенный коммит из окна, читает его файлы и дифф нужного файла.

get_ui_context → get_commit → get_commit_diff

04 / ИСТОРИЯ

«Что происходило в main за 20 коммитов?»

Список коммитов без диффов, затем подробности только по интересным.

get_history → get_commit

ПОДКЛЮЧЕНИЕ · МИНУТА

Три шага,
одна команда.

Точная команда для вашей установки — в самом 🌱 Twig: кнопка MCP рядом с BugHunter, затем Copy.

  1. 1

    Включите сервер

    Кнопка MCP в панели инструментов → MCP server: On. Выбор переживает перезапуск.

  2. 2

    Добавьте его агенту

    Скопируйте строку для Claude Code, таблицу для Codex или JSON для Cursor — пути уже подставлены.

  3. 3

    Спросите

    Перезапустите агента и спросите о репозитории. Если 🌱 Twig закрыт, агент получит понятный ответ, а не тишину.

Пути — пример для macOS. В Windows и Linux 🌱 Twig подставит свои; они показаны в окне MCP.

МОДЕЛЬ БЕЗОПАСНОСТИ

Контекст для агента,
а не ключи от репозитория.

01 / ВЫКЛЮЧЕН

Пока вы не включите

До выбора в 🌱 Twig нет ни сокета, ни слушателя. Выключили — сокет исчезает.

02 / ЛОКАЛЬНО

Без сетевого порта

Unix-сокет в папке, которую открывает только ваша учётная запись (0700, сокет 0600); в Windows — named pipe. TCP нет.

03 / ТОЛЬКО ЧТЕНИЕ

Без команд и записи

Нет run_command, shell и инструментов записи. Чтения рабочего дерева не трогают индекс: GIT_OPTIONAL_LOCKS=0.

04 / ГРАНИЦЫ

Только ваши репозитории

Агент не может указать произвольную папку: только подключённые в 🌱 Twig, пути проверяются на выход из репозитория.

Проверено, что ничего не меняется

Проверка 🌱 Twig вызывает каждый инструмент на настоящих репозиториях — с конфликтом merge, staged и unstaged правками, большими диффами — и сверяет папку .git и рабочее дерево побайтно до и после. Выделение в окне хранится только в памяти и никуда не записывается.

ЧЕСТНО

Чего пока нет
и что будет дальше.

Сейчас

  • Только чтение: агент не стейджит и не коммитит.
  • Только локальный stdio-мост; HTTP-транспорта нет.
  • Выделение внутри экрана staging агенту не передаётся; выбора ветки и ханка в 🌱 Twig нет — эти поля всегда null.
  • Живьём проверено на macOS; Windows и Linux используют тот же код, но ещё не прогонялись.

Дальше

  • Инструменты записи — stage_hunk, create_branch, create_commit — под отдельным разрешением.
  • Подтверждение каждой мутации в окне 🌱 Twig с точной командой.
  • Отмена действий агента тем же Undo, что и ваших.
