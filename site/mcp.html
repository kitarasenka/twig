ПОЧЕМУ ЭТО КРУТО

Не обёртка над git,
а смысловой API к репозиторию.

Агент может запустить git diff и сам. Поэтому инструмент здесь есть, только если он экономит агенту токены или вызовы — или даёт то, чего у git нет: что вы выделили в окне и ваше подтверждение коммита. Остальное агент спрашивает у git.

01 / ФОРМА GIT, БЕЗ ШУМА

Ответ в форме, которую модель уже знает

Файл — одна строка, как в git status --short, с числом строк; дифф — обычные ханки без заголовков diff --git и index. Ничего не экранируется в JSON, поэтому ответ не больше вывода git, а сводка — в 2–3 раза меньше (замер). Ветка, upstream и идущий merge или rebase — в короткой сводке.

02 / ОДИН ВЫЗОВ

Всё нужное — сразу

Все изменения с диффами — одним вызовом, коммит с сообщением и патчами — тоже. Lock-файлы и огромные файлы приходят одной строкой с причиной и командой git, которая их прочитает, а всё, что не влезло в ответ, дочитывается ещё одной командой. Поиск по истории возвращает только строки вокруг совпадения — в 3–63 раза меньше, чем git log -S … -p (замер).

03 / ЧТО ВЫДЕЛЕНО У ВАС

«Объясни этот коммит» — без хэша

Агент видит, какой коммит, диапазон сравнения или файл открыт в 🌱 Twig. Выделили строку в графе — спросили агента. Копировать хэш и путь больше не нужно.

04 / ТОЛЬКО ЧТЕНИЕ

Агент предлагает, решаете вы

Нет инструментов commit, stage, checkout, reset, push и нет запуска команд. План коммитов агент предлагает, а выполняете его вы — в 🌱 Twig, где staging построчный и почти каждое действие можно отменить.

05 / ВСЁ НА ВИДУ

Каждая команда агента — в журнале

Любая команда Git, которую вызвал агент, попадает в консоль 🌱 Twig с плашкой MCP: argv, каталог, вывод, код. Ваши действия во вкладке «My» не смешиваются с чтениями агента.

06 / ЛЮБОЙ КЛИЕНТ

Стандартный MCP, без облака

Обычный Model Context Protocol поверх stdio: никаких SDK провайдеров, аккаунтов и серверов. Мост запускается на исполняемом файле самого 🌱 Twig — отдельный Node.js не нужен.

Большой дифф не съедает контекст

Lock-файлы, минифицированные сборки и файлы больше 400 изменённых строк приходят одной строкой со счётчиками и причиной — 12 МБ сгенерированного JSON стоят одну строку. Каждая такая строка называет команду, которая прочитает файл. Мелкие файлы ложатся в бюджет ответа первыми; то, что не влезло, ответ в конце перечисляет одной командой git diff или git show. Файл никогда не обрывается посередине.

Как мерили

  • Новые файлы агент с git читает через cat — самый дешёвый способ. Всё, что 🌱 Twig пометил «не поместилось», дочитано той командой git, которую назвал ответ, — знания у обоих одинаковые. Список коммитов на стороне 🌱 Twig — тоже git log --oneline: короче его не сделать.

Здесь 🌱 Twig не перепаковывает,
а отбрасывает лишнее.

Что учесть

  • Описания двух новых инструментов — 1 007 токенов за сессию. Один вызов экономит от 2,5 до 186 тысяч.
  • Против аккуратного grep выигрыш скромнее: в обоих случаях агент читает примерно одни и те же строки кода, а 🌱 Twig вдобавок даёт тему коммита, дату и номера строк.
  • На файл — до 5 мест; остальные посчитаны, и ответ называет git show, который прочитает файл целиком.
  • get_blame не возвращает код: агент обычно уже прочитал файл. С code: true код приходит, этот вариант не мерили.

Как мерили

  • Так, как пишет агент: git log -S'запрос' -p; для blame — git blame -L и git log -1 на каждый коммит, который он назвал.
  • Сравнение с grep — для честности: такой конвейер агенты пишут редко.

9 ИНСТРУМЕНТОВ · 6 ЧИТАЮТ, 3 ПРЕДЛАГАЮТ КОММИТ

Только те,
что лучше git.

Обёрток над тем, что git и так отвечает коротко — git log --oneline, git diff -- файл, — нет: это агент запускает сам. Каждый инструмент принимает необязательный repository — имя, корень или любой путь внутри. Без него читается репозиторий рабочей папки агента, если он подключён, иначе открытый в 🌱 Twig — и тогда ответ первым делом называет его.

get_workspace_context

Сводка: ветка, upstream, операция, счётчики файлов, выделенное в окне и остальные подключённые репозитории.

list_changes

Изменённые файлы строками, как в git status, с +/− строк. С diffs: true — сразу с патчами, lock-файлы — строкой с командой git diff. Постранично.

get_commit

Коммит одним вызовом: сообщение, автор, родители и патч каждого файла. Lock-файлы и огромные файлы — строкой с командой git show.

search_history

Когда код появился или исчез (-S, -G), по сообщению или автору. Возвращает только строки вокруг совпадения, а не дифф коммита.

get_blame

Кто и зачем менял строки: куски строк по коммитам и тема каждого коммита один раз. Номера строк — как в редакторе.

get_ui_context

Что открыто в окне: вид, коммит, диапазон, файл. Чего 🌱 Twig не хранит — null.

propose_commit

Предлагает коммит всех изменений с сообщением агента. Окно показывает файлы и сообщение, а переключатели — поднять ли версию и поставить ли тег; Commit, Commit & Push или Cancel — ваш выбор. Выключен, пока вы не разрешите.

new_version

Предлагает выпуск: коммит с поднятой версией (patch, minor или major) и тегом по образцу прошлого — v1.2.3 → v1.2.4. Версию и тег вы меняете переключателями; Commit & Push отправляет коммит и тег.

await_commit

Ждёт вашего ответа дальше, если вы думаете дольше ~45 секунд, и отвечает тем же: хэш коммита, пуш или отмена.

МОДЕЛЬ БЕЗОПАСНОСТИ

Контекст для агента,
а не ключи от репозитория.

01 / ВЫКЛЮЧЕН

Пока вы не включите

До выбора в 🌱 Twig нет ни сокета, ни слушателя. Выключили — сокет исчезает.

02 / ЛОКАЛЬНО

Без сетевого порта

Unix-сокет в папке, которую открывает только ваша учётная запись (0700, сокет 0600); в Windows — named pipe. TCP нет.

03 / ТОЛЬКО ЧТЕНИЕ

Без команд и записи

Нет run_command, shell и инструментов записи. Чтения рабочего дерева не трогают индекс: GIT_OPTIONAL_LOCKS=0.

04 / ГРАНИЦЫ

Только ваши репозитории

Агент не может указать произвольную папку: только подключённые в 🌱 Twig, пути проверяются на выход из репозитория.

Проверено, что ничего не меняется

Проверка 🌱 Twig вызывает каждый инструмент на настоящих репозиториях — с конфликтом merge, staged и unstaged правками, большими диффами — и сверяет папку .git и рабочее дерево побайтно до и после. Выделение в окне хранится только в памяти и никуда не записывается.
