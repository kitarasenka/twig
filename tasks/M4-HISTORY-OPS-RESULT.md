# M4 — результат

Исходный отчёт автора: веха выполнена по плану `M4-HISTORY-OPS.md`.
Это не означает полного выполнения исходного брифа: см. независимую проверку ниже.
Проверено на macOS arm64,
Node 20.20.0, git 2.54.0: `npm test` — 13 проверок зелёные, `npm run test:smoke`
— четыре независимых сеанса Electron зелёные.

## Что сделано

**Контекстное меню коммита** (§8.2) — создать ветку, создать тег (аннотированный
при непустом сообщении), checkout ветки и checkout коммита с detached HEAD,
merge каждой ветки на этом коммите с `--no-ff` и без, rebase текущей ветки на
коммит, интерактивный rebase, cherry-pick, revert (`--mainline 1` для
merge-коммита), reset soft/mixed/hard, копирование sha и сообщения. Правая
кнопка и Shift+F10/Menu, стрелки, Home/End, Escape; фокус возвращается на ту же
строку истории.

**Merge, cherry-pick, revert, reset** — через единый исполнитель, с честным
разделением «остановилось» и «не смогло запуститься».

**Интерактивный rebase** (§8.3) — приложение подставляет себя как
`GIT_SEQUENCE_EDITOR` и `GIT_EDITOR` и не воспроизводит rebase своими силами.
Диалог: `pick/reword/edit/squash/fixup/drop`, перестановка перетаскиванием,
кнопками и Alt+стрелками, сводка и блокировка невозможных планов.

**Редактор конфликтов** (§8.5) — три стадии индекса, редактируемый результат,
построчный выбор с любым порядком сторон, быстрые «взять наше/их/оба/ничего»,
свой undo/redo, предупреждение об оставшихся маркерах, проверка mtime и размера
перед записью, `git add` как «решено», выбор стороны целиком для бинарных.

**Баннер прерванной операции** — вид операции, шаг N из M, ветка из
`head-name`, список конфликтных файлов, continue/skip/abort; continue
заблокирован, пока что-то конфликтует.

**Подтверждения §6.5** — точный текст команды и что именно потеряется.

## Что выяснилось про Git (проверено вживую, не по памяти)

1. `GIT_EDITOR` вызывается **один раз на цепочку** squash/fixup, а не на
   строку, и ещё раз на каждом `--continue` после конфликта. Позиционная
   очередь сообщений разъезжается. Сообщения привязаны к oid, который читается
   из последней строки `rebase-merge/done`.
2. `git merge --continue` не принимает **никаких** других аргументов —
   `--no-edit` отвергается. Единственный способ не повиснуть на vi — свой
   редактор на каждом вызове.
3. Обычный `git rebase` тоже создаёт `rebase-merge/` и файл `interactive`:
   отличить интерактивный от обычного по этому файлу нельзя.
4. Cherry-pick одного коммита из ветки с той же базой и теми же датами даёт
   **тот же** sha — это не ошибка.

## Сомнительные моменты

Записаны как есть, к обсуждению.

1. **Чтение служебных файлов `.git` напрямую.** У Git нет машинного формата для
   «какая операция идёт»: `--porcelain=v2` этого не содержит, а человеческий
   вывод `git status` парсить запрещено §6.3. Читаются `MERGE_HEAD`,
   `CHERRY_PICK_HEAD`, `REVERT_HEAD`, `rebase-merge/{msgnum,end,head-name}` —
   документированная раскладка каталога, но всё же не команда.
2. **`ELECTRON_RUN_AS_NODE=1` в окружении Git.** Так уже работал askpass с M1.
   Переменную наследуют все дети Git, включая хуки. На Electron-бинарник влияет
   только он сам, но формально мы меняем среду чужих процессов.
3. **Команды редакторов — строки для шелла.** `GIT_EDITOR="<путь> <скрипт>"`
   с кавычками; на Windows их разбирает bundled sh. Кавычки закреплены тестом,
   но на Windows это не запускалось (как и всё остальное).
4. **Парсер маркеров живёт в рендерере**, а не в `main/git/`. Редактор
   перечитывает текст на каждое нажатие клавиши, IPC на это — абсурд; модуль без
   единого импорта, его грузит и Vite, и Node в проверке. Место всё равно
   спорное.
5. **Перетаскивание строк между колонками не сделано.** §8.5 просит «перенос
   строк мышью внутри результата и из боковых колонок». Сделан построчный выбор
   с порядком сторон и свободное редактирование — то же самое достижимо и с
   клавиатуры. Полноценный drag-and-drop строк — отдельный объём и интеракция,
   недоступная без мыши.
6. **Пикшены выбора сбрасываются при изменении числа конфликтов.** Применение
   одного региона перенумеровывает остальные; вместо тихого смещения выбор
   очищается. Предсказуемо, но не бесплатно для пользователя.
7. **Меню строит план rebase из `<oid>..HEAD --no-merges`.** Это воспроизводит
   todo, который Git сгенерировал бы сам, но точного совпадения гарантировать
   нельзя для экзотических конфигураций (`rebase.rebaseMerges`, `--update-refs`).
   При расхождении Git откажется, и это будет видно в консоли.
8. **Предел плана — 1000 коммитов**, список не виртуализован. Выбрано с потолка.
9. **`deleteBranch` есть в Git-слое и покрыт тестом, но не выведен в IPC** —
   удаление веток относится к M5, а канал без экрана за ним — лишняя
   поверхность. Если это неверно, канал добавляется одной строкой.
10. **`--continue` после `edit` не даёт отдельного экрана.** Git останавливается,
    баннер это показывает, но «изменить коммит и продолжить» пользователь делает
    на экране рабочего дерева. Отдельного шага для `edit` нет.
11. **Undo/Redo в тулбаре по-прежнему заглушка** — это §8.1 и веха M5.
12. **Версия поднята до 0.2.0 (minor)** — новая функциональность. Уровень
    выбран по правилу репозитория без вопроса, потому что веха целиком про новые
    возможности; если нужен другой — скажите.

## Найдено тестами, а не ревью

- Меню открывалось без фокуса: замер размера идёт при `visibility: hidden`, а
  скрытый элемент молча отказывается принимать `.focus()`.
- `withState` глотал ошибки валидации и отвечал «не получилось» вместо отказа
  канала — четыре из пяти заведомо неверных вызовов IPC проходили. Теперь
  `TypeError` из билдеров argv всегда отклоняет запрос.
- Диалог rebase уезжал за край: базовый `dialog` — 480 px, а `<select>` в гриде
  имеет `min-width: auto` и распирал строку. Появился осознанный широкий вариант.
- «Merge did not finish» с открытием консоли на обычном конфликте — ложь.
  Остановка на конфликте больше не считается ошибкой.
- Refresh не перечитывал сам репозиторий: после смены ветки снаружи все подписи
  меню оставались от прежней ветки.

### Подтверждённые пробелы интерфейса

Дополнение при интеграции M5: в текущем `App.jsx` кнопка Branch всё ещё всегда
disabled, раскрывающихся меню Pull/Push нет, Pop не проверяет пустоту stash.
Наличие соответствующих Git-билдеров не означает доступность действий из
тулбара. Эти пробелы M3 пока только отмечены. Новые экраны менеджера репозиториев,
remotes и clone выполняются отдельно как согласованная часть M5.

1. `renderer/src/features/graph/HistoryWorkspace.jsx`: реальный `BranchTree`
   только выбирает вершину. Нет контекстного меню ветки, явной отметки текущей
   ветки; секций STASHES/REMOTES/SUBMODULES из §2.3 нет. `stashList` в API
   не заменяет просмотр содержимого stash в UI.
2. Нет полноценных селекторов репозитория и ветки с поиском, закрытия реальных
   вкладок, всех клавиатурных эквивалентов действий; демонстрационный экран
   остаётся частью старта. Сохранение состояния вкладки проверено только в
   текущем процессе, не как восстановление всего рабочего пространства.
3. `HistoryWorkspace.jsx` / `StageDiff.jsx`: цвет добавлений/удалений не равен
   подсветке синтаксиса; word diff отсутствует. Большие диффы и списки файлов
   не виртуализованы.
4. `ConflictEditor.jsx`: нет переноса строк мышью внутри результата и между
   колонками. Возможность получить тот же текст вручную не закрывает §8.5.
   База при обычных merge-маркерах доступна как полная версия, а не как
   выровненная построчная центральная колонка каждого конфликтного региона.
5. Ошибки часто открывают всю консоль, а не нужную запись. Точный argv есть в
   журнале, но проверка всех текстов подтверждений на совпадение с итоговым
   argv (включая служебные аргументы исполнителя) не выполнена.

### Аудит безопасности: требует отдельного исправления

- **Высокий приоритет — запись конфликтов через symlink.** В
  `main/git/conflicts.js` проверка `path.relative` защищает лишь лексический
  путь. `stat/readFile/writeFile` следуют симлинкам; конечный файл/родители
  не проверяются на выход за репозиторий. Возможность перезаписи внешнего
  файла следует из кода; эксплуатационный тест не проводился.
- **Внешние правки конфликтного файла.** Текстовое сохранение сверяет mtime и
  размер, но между stat и writeFile остаётся гонка; выбор целиком ours/theirs
  вообще не принимает снимок mtime/size. Отдельно проверить симлинки,
  delete/modify, удаление файла снаружи и бинарные версии. Отсутствующий
  рабочий файл сейчас приводит к ошибке `stat`, а не экрану выбора удаления.
- **Разрушающие подтверждения только в renderer.** Каналы reset/checkout/
  force-with-lease сами по себе не подтверждают действие в main. Это не
  обход проверки доверенного отправителя, но компрометация renderer обходит
  пользовательский диалог. Нужен отдельный выбор модели защиты.
- **Credentials не завершены ещё с M1.** Собственный askpass не спрашивает
  пароль/пассфразу в окне приложения. Проверки с локальным remote это не
  обнаруживают; существующий credential helper может работать независимо.
- Между sync/staging/history-ops нет общей очереди мутаций репозитория.
  Git блокирует свой index, но это не гарантирует согласованность UI и будущих
  инверсий Undo/Redo. Новый sync автоматически отменяет предыдущий по cwd.

### Аудит производительности и надёжности: открытые вопросы

- `exec.js` отменяет только непосредственный процесс Git, не гарантируя
  остановку SSH/helpers/потомков. Отмена не означает откат уже выполненных
  Git-изменений. Требуются отдельные тесты для каждой ОС.
- Журнал append-only читается целиком при старте; лимит 2000 относится к
  набору записей в памяти, а не к размеру файла. Вывод крупных diff/blob
  не ограничен; обновления консоли копируют записи/строки. Это риск памяти
  и задержек, а не подтверждённый замер зависания.
- `loadMore` заново строит Set всех загруженных oid и копирует массивы;
  `indexMap` пересчитывается на каждой странице. Git `--skip` и раскладка
  большого числа дорожек также требуют профиля на реалистичной истории.
- История по страницам не привязана к неизменному снимку refs: дубль oid
  вызывает просьбу refresh, но внешняя перезапись истории может дать пропуски
  без дублей. Заголовок графа и широкий горизонтальный скролл требуют проверки.
- Конфликтный редактор хранит до 100 полных текстовых снимков, при разрешённом
  файле 5 MB это заметный расход памяти. Лимит рабочего файла не ограничивает
  размеры стадий, загружаемых через `git show`.
- Ошибка загрузки «all files» и fallback `ops:state` к `none` требуют проверки:
  ошибка чтения не должна выглядеть как бесконечный скелетон или отсутствие
  прерванной операции.
- Планы rebase >1000, экзотические настройки Git, SHA-256 репозитории,
  git worktree/submodule, конфликтные кодировки кроме UTF-8 и native Windows/
  Linux не покрыты текущими end-to-end проверками. Не считать их поддержкой,
  доказанной зелёным `npm test`.

Полноценный финальный UI/UX-review, упаковка и инверсии операций остаются M5.
Здесь не выполнялись исправления перечисленных пробелов и рисков.
