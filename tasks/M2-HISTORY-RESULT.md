## Источник правды: реальный git, не только man

Помимо `git help log` и `git help for-each-ref` (git 2.54.0), формат сверен
байт-в-байт на настоящем выводе в этом репозитории — важно, потому что
документация не полностью специфицирует границы записей при кастомном
`--format` в сочетании с `-z`:

- **`git log -z --format=...`**: `-z` заменяет обычный завершающий перевод
  строки после каждой записи на NUL. Формат парсера использует 7 `%x00`
  между 8 полями и **не** добавляет восьмой `%x00` в конец — его подставляет
  сам `-z`. Итог: ровно 8 NUL-разделённых токенов на коммит, без лишнего
  разделителя между коммитами. Проверено на root-коммите (`%P` → пустая
  строка), merge-коммите (`%P` → два хэша через пробел) и многострочном теле
  с кириллицей.
- **`git for-each-ref --format=...`**: у этой команды **нет** флага `-z` —
  разделитель записей всегда `\n`, независимо от формата. Если добавить
  собственный `%00` в конец формата (что я сначала и попробовал), запись
  оканчивается на `\0\n`, и этот `\n` приклеивается к началу *следующей*
  записи как часть её первого поля — проверил на реальном выводе, это видно
  прямо в байтах. Поэтому формат парсера использует ровно 7 `%00` для 8 полей
  **без** завершающего `%00`, и `refs.js` сначала делит вывод по `\n`
  (по строкам-записям), а уже внутри строки — по `\0` (по полям). Это
  безопасно, потому что ни один из выбранных атомов (имя ссылки, hex id,
  фиксированный enum `objecttype`, короткая строка трекинга) не может
  физически содержать перевод строки — в отличие от `git log`, где тело
  коммита обязано быть на месте и обязано содержать переводы строк.
- **`%(symref)`** непусто только у символических ссылок (`refs/remotes/*/HEAD`
  наблюдал вживую: `symref = refs/remotes/origin/main`) — по этому полю
  ссылка отбрасывается целиком, а не превращается в обычную ветку.
- **`%(upstream:track)`** пуст при синхронизированной ветке (проверено вживую
  на `main`/`feat/git-desk` с настроенным upstream), а не `"[]"` — это отличает
  «нет upstream» (`%(upstream)` пуст) от «upstream есть, но расхождения нет».
  `"[ahead N]"`, `"[behind M]"`, `"[ahead N, behind M]"` и `"[gone]"` не
  воспроизвёл вживую (в этом чекауте нет расходящихся веток и удалённых
  upstream-ref), поэтому эти случаи покрыты фикстурами по документации
  git-for-each-ref(1), а не реальным выводом — см. «Ограничения».
- **`%(*objectname)`** (дереференс тега) тоже не воспроизвёл вживую — в этом
  репозитории нет ни одного annotated-тега (проверил `git cat-file -t` по
  всем тегам) — покрыт фикстурой по документации.

## Контракт

Реализован как в задаче:

```js
// history-parser.js
export function parseHistoryV1(output) { /* => Commit[] */ }

// history.js
export async function loadHistoryPage({ cwd, log, limit = 250, skip = 0 })
// => { commits: Commit[], nextSkip: number | null }

// refs.js
export function parseRefsV1(output)
export async function loadRefs({ cwd, log })
```

`loadHistoryPage` запускает ровно
`git log --all --topo-order -z --format=<парсерский формат> --max-count=<limit> --skip=<skip>`
через существующий `runGit()`; `-z` не был явно назван в задаче, но обязателен
— без него `git log` разделяет записи обычным `\n`, который тело коммита
может содержать сколько угодно раз, и границы коммитов стали бы неразличимы.
Даты — `%aI`/`%cI` (строгий ISO-8601 с офсетом уже по умолчанию, без
`--date=iso-strict`). `refs.js` запускает `git for-each-ref --format=<...>
refs/heads refs/remotes refs/tags` — без `git branch`/`git tag`/decorate, как
требовалось.

## Расхождения с контрактом (решения принял сам, не менял контракт молча)

1. **Экспортированы `HistoryParseError` и `RefsParseError`.** Тот же довод,
   что и в M1 для `StatusParseError`: вызывающему коду нужно отличать «Git
   прислал неожиданный формат» от прочих ошибок. Формы результата это не
   меняет.
2. **Экспортированы `buildHistoryArgv({ limit, skip })` и `buildRefsArgv()`.**
   Задание само предложило этот путь: «loadHistoryPage через подставной
   runGit невозможно без изменения exec, поэтому проверь его аргументы
   выделением чистого builder-а». Сделал то же для `refs.js` для
   симметрии — оба самопроверочных скрипта проверяют точный `argv` без
   единого вызова Git. Валидация `limit`/`skip` (целое, 1–500 / ≥0) живёт
   внутри `buildHistoryArgv`, `loadHistoryPage` её не дублирует.
3. **`git log --all` включает `refs/stash`, если стеш есть.** `--all`
   у git-rev-list — это все ссылки под `refs/`, включая `refs/stash` (это не
   `refs/heads/*` namespace, а отдельный ref верхнего уровня, но физически
   он тоже под `refs/`). Задание прямо требует `git log --all --topo-order`
   — сделал ровно так, — но `PROMPT.md` §2.3 держит стеш отдельной секцией
   сайдбара, а не строкой основной истории. Если коммит(ы) стеша не должны
   попадать в основной список — нужен `--exclude=refs/stash` или фильтрация
   выше по стеку; сам не стал угадывать это решение, помечаю для интеграции.
4. **`upstream:track = "[gone]"`**: контракт описывает только `upstream: null`
   при отсутствии апстрима и числа при наличии. Для «апстрим сконфигурирован,
   но remote-ветка исчезла» контракт молчит. Решил: имя апстрима отдаётся как
   есть, `ahead`/`behind` = `0` (посчитать расхождение против несуществующей
   ссылки нельзя). Задокументировано в JSDoc `parseUpstream`.

Покрытие `scripts/checks/history.mjs`:
- пустой вывод; одиночный коммит; root-коммит (`%P` пуст, тело пусто);
  merge с двумя родителями; SHA-1 и SHA-256 (включая как родителя);
  несколько коммитов подряд без лишнего разделителя между ними;
- тема/тело с кириллицей, emoji, табом, переводом строки и строкой, похожей
  на hex-хэш — не переинтерпретируется как поле;

- ошибки: не-строка, оборванный поток (нет конечного NUL), число полей не

Покрытие `scripts/checks/refs.mjs`:
- пустой вывод; local-ветка в синхроме; local-ветка без апстрима; ahead-only/
  behind-only/оба сразу; `[gone]`; remote-ветка; символическая remote HEAD
  (отбрасывается); lightweight и annotated тег (дереференс `target` на
  коммит, не на объект тега); SHA-256; сортировка local → remote → tag и
  `localeCompare('en')` внутри группы, включая диакритику (`álpha` перед
  `main`); имя ветки с `/`-иерархией (`feat/git-desk`) остаётся как есть для
  папочной группировки сайдбара;
- ошибки: не-строка, оборванный поток (нет конечного `\n`), число полей не
  кратно 8, битый object id, недопустимый `objecttype`, неизвестный
  namespace ссылки (`refs/notes/*`), синтаксически некорректный track
  (`"[]"`, `"ahead 3"` без скобок); сообщение об ошибке не содержит утёкшего
  имени ссылки;
- `buildRefsArgv()`: точный ожидаемый argv.

## Аудит безопасности

- Ни `history.js`, ни `refs.js` не запускают `git` напрямую — только через
  существующий `runGit()` из `exec.js` (`spawn`, `shell: false`, уже
  проверенный в M1). Парсеры сами не исполняют ничего.
- `limit`/`skip` валидируются как целые числа в заданных границах до
  формирования `argv` — нельзя передать в `--max-count=`/`--skip=` что-либо,
  кроме десятичной цифровой строки; инъекция аргументов через эти параметры
  исключена на уровне типов (`Number.isInteger`), а не только regex на
  результат.
- Сообщения об ошибках парсеров — статические литералы, не включают hash,
  имена веток, сообщения коммитов и прочие данные репозитория. Проверено
  тестами для обоих парсеров на кейсах с «секретным» текстом рядом с местом
  ошибки.
- `refs.js` явно ограничивает namespace тремя ожидаемыми префиксами и
  отвергает всё остальное (`refs/notes/*` и подобные) с понятной ошибкой —
  не пытается угадать тип по эвристике имени.

## Аудит производительности

- Оба парсера — один линейный проход: `split('\0')`/`split('\n')` + один
  `for`/`for..of` без вложенных сканирований всего входа целиком.
  `history-parser.js` берёт `FIELD_COUNT`-группы через `slice` на каждый шаг
  цикла — количество таких `slice` линейно числу коммитов, не квадратично.
- `loadHistoryPage` — постраничная загрузка (`--max-count`/`--skip`), не
  тянет всю историю разом; `nextSkip` вычисляется без дополнительного
  обращения к Git. Тестов на реальных 100k коммитов не проводил — эта веха
  того не требовала (запуск Git запрещён в самопроверках), только синтетика.
- `refs.js` загружает все ссылки одним вызовом `for-each-ref` (не по одной
  на ветку/тег), сортировка — один проход `Array.prototype.sort`.

## Ограничения

- `"[ahead N]"`, `"[behind M]"`, `"[ahead N, behind M]"`, `"[gone]"` и
  дереференс annotated-тега (`%(*objectname)`) не воспроизведены на живом
  git в этом чекауте (нет расходящихся веток, удалённых upstream-ref и
  annotated-тегов) — покрыты фикстурами по документации
  git-for-each-ref(1), не по факту. Стоит перепроверить на репозитории, где
  такие ссылки реально есть, прежде чем полагаться на это в проде.
- `git log --all` включает `refs/stash` — см. пункт 3 в «Расхождения с
  контрактом»; решение о фильтрации стеша из основной истории не принимал.
- `loadHistoryPage`/`loadRefs` не тестировались с реальным `runGit`
  (задание явно запретило запускать Git в этой части), только чистые
  парсеры и `argv`-билдеры. Интеграционную проверку с настоящим
  репозиторием делает Codex.
- Не проверял поведение на Windows/Linux (переводы строк CRLF в теле
  коммита теоретически возможны при специфичной настройке `core.autocrlf`
  на стороне автора коммита, но это часть исходного сообщения, а не
  разделитель парсера — не должно ломать парсинг, просто отразится как есть
  в `body`, отдельно не тестировал).

## Передать Codex

`main/git/history.js` (`loadHistoryPage`), `main/git/history-parser.js`
(`parseHistoryV1`, `HistoryParseError`) и `main/git/refs.js` (`loadRefs`,
`parseRefsV1`, `RefsParseError`) готовы к подключению. Оба loader'а зовут уже
существующий `runGit()` — новых точек запуска Git нет. Два открытых вопроса
для интеграции: (1) нужно ли исключать `refs/stash` из `git log --all` в
`history.js`, если стеш не должен попадать в основной список коммитов
(сейчас попадает буквально, как просил контракт); (2) `"[gone]"`-апстрим и
дереференс annotated-тега проверены только по документации git, не на живых
данных — стоит прогнать на репозитории с такими ссылками перед релизом
M2. Самопроверки не трогают `exec.js`/IPC и не запускают Git. M2 в целом не
завершён — это только Git-слой истории и refs.
