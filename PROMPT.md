репозиторий, прочитать этот файл и продолжить работу с того места, где она стоит. Файл —
источник правды по задаче: решение изменилось — правь этот файл в том же коммите, что и код.

## 1. Задача одной фразой

Сделать в `modules/git_desk/` **десктопное приложение** (macOS, Windows, Linux) — графический
 git-клиент, у которого главный экран это **визуальное дерево коммитов**, действия делаются
кнопками на верхней панели и через контекстное меню на коммитах, а всё, что приложение
выполняет, видно в **консоли команд** внизу.

Каркас главного окна:
```text
┌─ tabs ──────────────────────────────────────────────────────────────────────────────┐
│ ⌂  Release Notes │ ⑂ nodes-managers ✕ │ ⑂ youta │ +           🔔  ⚙  👤 ktarasenka  │
├─ toolbar ───────────────────────────────────────────────────────────────────────────┤
│ repository            branch      │ Undo Redo │ Pull▾ Push │ Branch Stash Pop │ >_   │
│ nodes-managers ▾  ›   main ▾      │  ↺    ↻   │  ↓     ↑   │   ⑂     ⤓    ⤒   │Term. │

│              │                                              │ [Path│Tree] ☐ all     │
│              │                                              │ ✎ modules/bat_bus/…   │
├──────────────┴──────────────────────────────────────────────┴───────────────────────┤
```

Референс — GitKraken. **Копировать один в один не нужно и нельзя**: нужна та же анатомия окна
(табы репозиториев → тулбар действий → сайдбар секций → центральное дерево → правая панель
коммита → нижняя консоль) и та же плотность информации, но собственная айдентика: свои цвета,
свои иконки, своё имя. Ничьи логотипы, шрифты-марки и точные палитры чужого продукта не тащить.

## 2. Как выглядит окно (компонентная спецификация)

### 2.1. Табы репозиториев (верх)

Открытые репозитории — вкладками, каждая с иконкой ветки и именем, закрытие крестиком, `+`
открывает пустую вкладку с экраном «открыть / склонировать / из списка». Справа — уведомления
(результаты фоновых fetch и ошибки), настройки, профиль. Переключение вкладок сохраняет
состояние экрана: скролл дерева, выделенный коммит, фильтры.

### 2.2. Тулбар действий

Слева — селектор репозитория и селектор текущей ветки (оба выпадающие, с поиском).
Дальше — группы кнопок, каждая **иконка + подпись** (не голые иконки: незнакомую иконку
 git-клиента невозможно угадать):

| Группа | Кнопки |
| --- | --- |
| История действий | **Undo**, **Redo** |
| Синхронизация | **Pull** (со стрелкой-меню: pull, pull --rebase, fetch, fetch --prune), **Push** (в меню: push, set upstream, force-with-lease) |
| Ветки и карман | **Branch** (создать от HEAD), **Stash**, **Pop** |
| Прочее | **Terminal** (показать/скрыть консоль), справа — **Actions** и **Search** |

Неприменимая кнопка — **выключена и объясняет причину в подсказке** («Redo: следующего действия
нет», «Pop: стеш пуст»). На кнопках Pull/Push — бейдж с числом входящих/исходящих коммитов.
Идущая операция показывает прогресс прямо на кнопке и даёт её отменить.

### 2.3. Левый сайдбар

Поле фильтра сверху (сочетание клавиш подписано в плейсхолдере). Ниже — сворачиваемые секции со
счётчиками: **LOCAL**, **REMOTE**, **STASHES**, **TAGS**, **REMOTES**, **SUBMODULES** (последняя
— только если есть). Текущая ветка выделена, у веток с расхождением — `↑2 ↓1`. Ветки, где имя
похоже на путь (`feat/x/y`), группируются в дерево папок. Контекстное меню на элементе повторяет
меню коммита из §8.2, применённое к вершине ветки. Сайдбар сворачивается в узкую полосу.

### 2.4. Центр: дерево коммитов

Таблица с колонками `BRANCH / TAG` · `GRAPH` · `COMMIT MESSAGE` · (автор) · (дата).

- **GRAPH** — DAG с вертикальными дорожками: цветная линия на ветку, узлы-кружки, слияния и
  ответвления рисуются кривыми, а не ступеньками. Цвет дорожки стабилен для ветки в пределах
  сессии.
- Строка HEAD помечена галочкой и плашками веток/тегов, `origin/*` отличается от локальной.
- В строке — тема коммита обычным цветом плюс начало тела приглушённым, обрезанное многоточием
  (как на референсе: `fix(bat_bus): …  Технически: | - версия …`).
- Справа — относительная дата (`21 hours ago`), а между строками разных суток — тонкий
  разделитель с датой.
- Незакоммиченные изменения — **первой строкой дерева** («Uncommitted changes, N files»), клик
  открывает экран рабочего дерева (§8.6).
- Виртуализованный список: 100k коммитов листаются без лагов, история догружается страницами.
- Клик — выбор, двойной клик — checkout (с подтверждением), правая кнопка — меню (§8.2),
  Shift-клик — выбор диапазона (дифф между двумя коммитами).

### 2.5. Правая панель коммита

Короткий sha в заголовке, полное сообщение (тема крупнее, тело моноширинным), автор с аватаром
(инициалы, если аватара нет), даты author/commit, ссылки на родителей (клик — переход к
родителю). Ниже — «N modified» и список файлов с переключателем **Path / Tree**, сортировкой и
галочкой «показать все файлы». Клик по файлу — дифф в основной области. Панель закрывается и
тянется по ширине.

### 2.6. Консоль (низ)

См. §7. По умолчанию свёрнута в одну строку со статусом последней команды, разворачивается
кнопкой Terminal или горячей клавишей.

### 2.7. Общие правила интерфейса

- **Тёмная тема — основная**, светлая обязательна и переключается в настройках; выбор темы
  системы уважается по умолчанию.
- Плотность как на референсе: строка дерева ~28–32 px, шрифт интерфейса 13–14 px, моноширинный
  для sha, диффов и консоли.
- Никакого «сначала пустой экран, потом всё разом»: скелетоны на дереве и списке файлов.
- Каждое действие мышью имеет клавиатурный эквивалент; хоткеи видны в меню и подсказках.
- Пустые состояния объясняют, что сделать («Нет подключённых репозиториев — открыть или
  склонировать»), а не показывают пустоту.
- Ошибка git — не модалка со stderr, а понятная строка + кнопка «показать вывод» (открывает
  консоль на нужной записи).
- Доступность: контраст текста ≥ 4.5:1, фокус виден, дерево и списки проходятся с клавиатуры,
  цвет никогда не единственный носитель смысла (у веток и статусов есть иконка/подпись).

## 4. Главное ограничение: это НЕ сервис под PM2

Остальные модули репозитория — боты и сервисы, которые сервер поднимает сам через
`ensureModules()` по наличию `nodex.json`, а PM2 держит по `ecosystem.config.cjs`. `git_desk` —
десктопное приложение, оно запускается на машине человека. Поэтому:

- **не создавай `modules/git_desk/nodex.json`** — иначе сервер будет пытаться поднять Electron
  без дисплея на боксе Hetzner и ронять его в бесконечном рестарте;
- **не добавляй запись в `ecosystem.config.cjs`**;
- на `server/` не рассчитывай: приложение автономно.

`npm run install:modules` (`tools/install-modules.js`) заходит в каждый каталог модуля с
`package.json` и делает `npm install` — для `git_desk` это Electron на сотни мегабайт, в том
числе на боксе. Добавь опт-аут: поле `"nodexInstall": false` в `modules/git_desk/package.json` и
его проверку в `tools/install-modules.js` (каталог пропускается с явной строкой в логе). Правка
`tools/` — часть задания.

## 5. Стек (зафиксирован)

- **Electron** — один код на три платформы в JS, а репозиторий целиком на JS/Node 20 ESM.
- **React 18 + Vite** в рендерере — как в `web/` и `modules/bat_bus/miniapp`.
- **JavaScript ESM**, не TypeScript — так пишет весь репозиторий. JSDoc там, где форма данных
  неочевидна.
- **Граф рисуй сам** — SVG/canvas поверх виртуализованного списка. Готовые библиотеки графов
  коммитов не тянуть: раскладка дорожек — 200 строк кода и полный контроль над рендером.
- **electron-builder** — `dmg` (mac x64 + arm64), `nsis` (Windows x64), `AppImage` + `deb`
  (Linux x64). Подписи и нотаризации нет — в README честно про предупреждение Gatekeeper.
- **Никаких обёрток над git** (`simple-git`, `isomorphic-git`): только системный `git` через
  `child_process.spawn`, причина в §6.
- Тесты и линт как в `bat_bus`: `eslint` + самопроверки скриптами на Node под одним `npm test`.
  Jest не тащить. Обязательные самопроверки: раскладка дорожек графа на фикстурах, парсер
  `--porcelain=v2`, слияние конфликтного файла, инверсии операций из §8.1.

## 6. Как исполняются git-команды (правила, а не пожелания)

1. Только `spawn("git", argv, { cwd })`, **`shell: false` всегда**. Никакой склейки строки: имя
   ветки `foo; rm -rf ~` должно остаться именем ветки.
2. Один исполнитель `main/git/exec.js` — единственное место, откуда запускается `git`.
   Возвращает `{ argv, cwd, code, stdout, stderr, ms, startedAt }` и в тот же момент пишет
   запись в журнал (§7). Вызов git мимо него — баг: консоль начинает врать.
3. Всегда `--no-pager` и `-c color.ui=false`; там, где вывод парсится — машинный формат
   (`--porcelain=v2`, `-z`, `--format=%H%x00%P%x00…`). Человекочитаемый вывод не парсим.
4. `GIT_TERMINAL_PROMPT=0` и свой `GIT_ASKPASS`, чтобы git не завис на невидимом промпте пароля;
   пароль и пассфраза спрашиваются окном приложения.
5. Разрушающее подтверждается диалогом с точным текстом команды и того, что потеряется:
   `reset --hard`, `push --force*` (только `--force-with-lease`), `clean`, `stash drop`,
   `branch -D`, rebase опубликованного, checkout с потерей незакоммиченного.
6. Сетевые операции (`clone`, `fetch`, `push`, `pull`) отменяемы: отмена убивает процесс, UI
   откатывается.
7. При старте — проверка наличия и версии git; нет git — экран с инструкцией под текущую ОС.

## 7. Консоль команд

Нижняя панель, журнал **всех** запусков git, включая фоновые (`fetch`, `status` после действия):

- строка ровно того argv, что ушёл в spawn: `$ git rebase --onto main feature~3 feature`, плюс
  `cwd`, время старта, длительность, код возврата; ненулевой код подсвечен;
- разворачивается в полный stdout/stderr;
- фильтр «только мои действия / всё», поиск по журналу, копирование строки и блока;
- живой поток вывода у долгих команд (прогресс clone/push виден по мере поступления);
- переживает перезапуск (последние 2000 записей в `app.getPath("userData")`), append-only.

Ввод произвольных команд в консоль — **не в первой версии**: приложение показывает, что делает,
а не подменяет терминал.

## 8. Функциональность

### 8.1. Undo / Redo

Это отмена и повтор **действий приложения**, а не `git checkout -`. Журнал операций: каждая
операция знает, как её обратить; обратная выполняется тем же исполнителем и так же видна в
консоли.

| Операция | Отмена |
| --- | --- |
| commit | `git reset --soft HEAD@{1}` (если после коммита ничего не делали) |
| stash push | `git stash pop` |
| stash pop/apply | `git stash push` с тем же набором файлов |
| создание ветки | `git branch -d` |
| checkout | checkout прежней ревизии |
| merge (без пуша) | `git reset --hard ORIG_HEAD` — с подтверждением |
| revert | `git reset --hard` на сохранённый sha — с подтверждением |
| push, pull, rebase опубликованного | **необратимо** |

Необратимая операция обрывает цепочку: Undo гаснет и в подсказке объясняет, почему («push уже
опубликован, откат — только force-push»). Не изображай отмену там, где её нет, и не храни теневых
копий рабочего дерева.

### 8.2. Контекстное меню на коммите

Создать ветку отсюда · создать тег · checkout · **merge** этой ветки в текущую (с опцией
`--no-ff`) · **rebase** текущей ветки на этот коммит, в том числе интерактивный (§8.3) ·
cherry-pick · revert · reset `--soft/--mixed/--hard` · копировать sha · копировать сообщение.
Показывай только применимое: неприменимого пункта не должно быть вовсе, кроме случаев, где
полезнее объяснить причину.

### 8.3. Интерактивный rebase

Список коммитов с действиями `pick / reword / edit / squash / fixup / drop` и перетаскиванием
для смены порядка. Приложение подставляет себя как `GIT_SEQUENCE_EDITOR` (и `GIT_EDITOR` для
reword), а не воспроизводит rebase своими силами. Остановки (конфликт, `edit`) — баннер над
деревом с кнопками «продолжить / пропустить / прервать»; тот же баннер для merge и cherry-pick.

### 8.4. Пользовательская зона

- **Профиль git**: `user.name`, `user.email` глобально и для репозитория, `core.editor`,
  `pull.rebase`, `init.defaultBranch` — через `git config`, файлы руками не редактировать.
- **SSH**: ключи из `~/.ssh` с типом и отпечатком, генерация (`ssh-keygen -t ed25519`),
  копирование публичного ключа, редактор `~/.ssh/config` (построчный и текстом) с бэкапом перед
  записью и валидацией синтаксиса; права соблюдать — `700` на каталоге, `600` на ключах и
  config. Кнопка проверки соединения (`ssh -T git@github.com`) с выводом в консоль.
- **Репозитории**: список подключённых, добавить каталог, склонировать по URL, убрать из списка
  (**не с диска**), переключение. Список в `userData`, наличие каталогов проверяется при старте.
- **Remotes**: добавить, изменить URL, удалить, `fetch --prune`.

### 8.5. Редактор конфликтов

Открывается на конфликтующем файле после merge/rebase/cherry-pick/stash pop.

- Три версии — «наше», «база», «их» — плюс редактируемый результат. Бинарные файлы: выбор
  целиком «наше/их», без псевдоредактора.
- Работа **построчно**: у каждой конфликтной строки — взять нашу, взять их, взять обе в любом
  порядке, пропустить; **перенос строк** мышью внутри результата и из боковых колонок в
  результат; свободное редактирование текста в любом месте.
- Своя отмена/повтор внутри редактора, независимая от глобальной (§8.1).
- Сохранение на диск, затем `git add <file>` как явное «решено»; счётчик оставшихся конфликтов и
  кнопки «продолжить» / «прервать».
- Перед сохранением проверка на остатки маркеров `<<<<<<<`, `=======`, `>>>>>>>`: предупредить,
  но дать сохранить осознанно.
- Файл мог измениться снаружи — сверяй mtime и не затирай чужие правки молча.

### 8.6. Рабочее дерево и остальное

Экран изменений (staged / unstaged / untracked) с постановкой в индекс по файлу и по куску
(hunk), дифф с подсветкой синтаксиса и режимом «слово в слово», окно коммита с проверкой
сообщения, список веток с поиском, список стешей с просмотром содержимого, blame по файлу,
поиск по истории (по сообщению, автору, файлу).

## 9. Архитектура

```text
modules/git_desk/
  package.json          # name: git-desk, private, type: module, "nodexInstall": false
  README.md             # установка, сборка, что умеет, ограничения
  CLAUDE.md             # состояние модуля для следующего агента
  design/
    TOKENS.md           # палитра, шрифты, отступы — итог прогона ui-ux-pro-max
    reference-*.png     # референсные скриншоты
  main/                 # процесс Electron (Node): окна, IPC, git, файлы, конфиг
    index.js  ipc.js  store.js
    git/exec.js         # единственная точка запуска git (§6)
    git/*.js            # status, log, graph, branches, stash, remotes, conflicts
  preload/index.js      # contextBridge: узкий API, без ipcRenderer наружу
  renderer/src/
    app/                # окно, табы, тулбар, раскладка панелей
    features/graph/     # раскладка дорожек + рендер дерева
    features/commit/  features/worktree/  features/conflicts/
    features/console/  features/settings/
    ui/                 # кнопки, меню, списки — на токенах из design/TOKENS.md
  scripts/checks/*.mjs  # самопроверки под npm test
  build/                # иконки и конфиг electron-builder
```

Безопасность Electron не обсуждается: `contextIsolation: true`, `nodeIntegration: false`,
`sandbox: true`, внешние ссылки — во внешний браузер, навигация окна на чужие URL запрещена.
Рендерер не видит ни `fs`, ни `child_process` — только явные IPC-каналы с валидацией аргументов
на стороне main. Никаких сетевых обращений, кроме тех, что делает сам git. Ни телеметрии, ни
автообновлений в первой версии.

## 10. Вехи

По одной за раз, каждая — отдельный коммит и запускаемое приложение. После каждой обнови
«Состояние» в `modules/git_desk/CLAUDE.md`.

- **M0. Каркас и облик.** Electron + Vite + React запускается, прогон `ui-ux-pro-max`,
  `design/TOKENS.md`, пустая раскладка главного окна (табы, тулбар, сайдбар, центр, правая
  панель, консоль) на заглушках. Тёмная и светлая темы. `npm test` зелёный, опт-аут в
  `install-modules.js`.
- **M1. Исполнитель и консоль.** `git/exec.js`, журнал, живая консоль, определение git. Открытие
  репозитория, ветка и статус в тулбаре.
- **M2. Дерево.** Граф с дорожками, виртуализация, строка незакоммиченных изменений, правая
  панель коммита со списком файлов и диффом, сайдбар с ветками/тегами/стешами.
- **M3. Рабочее дерево и синхронизация.** Staging по файлам и hunk'ам, Commit, Stash, Pop, Pull,
  Push с бейджами расхождения.
- **M4. Операции над историей.** Контекстное меню коммита, merge, cherry-pick, revert, reset,
  интерактивный rebase, редактор конфликтов, баннер прерванной операции.
- **M5. Пользовательская зона и сборка.** Профиль, SSH, репозитории, remotes, Undo/Redo (§8.1),
  сборка electron-builder под три платформы, финальный UI/UX-ревью скиллом.

Кросс-платформенность проверяй по ходу, а не в M5: пути через `path`, `spawn` без `shell` (на
Windows это обязательно), переводы строк и `core.autocrlf` учтены в диффах и конфликтах,
хоткеи — `Cmd` на macOS и `Ctrl` на остальных.

## 11. Правила репозитория, которые касаются задачи

- **Версионирование.** Любой коммит, трогающий `modules/git_desk/`, поднимает `version` в
  `modules/git_desk/package.json` **в том же коммите**. Уровень спрашивай у пользователя:
  `minor` (по умолчанию), `patch`, `major`. Первый коммит — `0.1.0`.
- **Коммиты** по-английски, тело — техническое «что и почему». Процедура: `.claude/skills/commit/`
  (Claude Code) или §3.1 `AGENTS.md` (Codex).
- **Комментарии в коде** — только для неочевидной логики (правило корневого `CLAUDE.md`).
- **Документация модуля.** Заведи `modules/git_desk/CLAUDE.md` по образцу
  `modules/cc_bridge/CLAUDE.md`: что это, состояние (сделано / не сделано), как запускать и
  собирать, ключевые решения и запреты. Допиши строку про `git_desk` в таблицу модулей
  `AGENTS.md` — с пометкой, что это десктопное приложение и под PM2 оно не живёт.
- **Язык.** Общение с пользователем — по-русски. Код, коммиты, идентификаторы и строки интерфейса
  приложения — по-английски.

## 12. Чего не делать

- Не трогать `server/`, `web/` и другие модули; из общего — только `tools/install-modules.js` и
  таблица модулей в `AGENTS.md`.
- Не добавлять `nodex.json` и записи в PM2 (§4).
- Не копировать чужой продукт пиксель в пиксель, не тащить чужие логотипы и названия.
- Не встраивать реализацию git на JS и не заменять системный git.
- Не делать «умных» автодействий за спиной: авто-`gc`, авто-stash, авто-push, авто-`--force`.
  Приложение делает то, что нажали, и показывает это в консоли.
- Не хранить пароли и токены открыто: только системный keychain через git credential helper.
- Не верстать экран, не прогнав его через `ui-ux-pro-max` (§3).
- Не начинать M5, пока M1–M4 не запускаются.

## 13. Как продолжить в новой сессии

> Прочитай `modules/git_desk/PROMPT.md` и `modules/git_desk/CLAUDE.md`, продолжи с текущей вехи.

## 14. Уточнения реализации M0

- Исходник `preload/index.js` остаётся ESM. Сборка преобразует его в
  `dist/preload/index.cjs`: sandboxed preload Electron не поддерживает ESM непосредственно.
  Это не меняет `sandbox: true`; CommonJS используется только в сборочном артефакте.
- M0 содержит явно обозначенный demo workspace, а не доступ к настоящему репозиторию.
  Первое подключение git и журнал команд — M1. Данные демонстрации не пишутся в журнал.
- Первая версия 0.1.0; следующая веха начинается только после отдельного коммита M0.
- M0 использует Electron 41.7.1 и electron-builder 26.0.12 с lock-файлом:
  следующие установщики/зависимости требуют Node 22.12, а §5 фиксирует Node 20.
  Перед выпуском M5 пересмотреть совместимость и актуальность этих версий.

## 15. Визуальная айдентика (уточнение пользователя)

## 16. Параллельная работа над M1

По просьбе пользователя независимая задача для Claude описана в
`tasks/M1-STATUS.md`: чистый парсер porcelain-v2 и собственные проверки.
Codex отвечает за исполнитель, журнал, IPC/preload, открытие репозитория,
консоль и итоговую интеграцию. Границы файлов и контракт парсера зафиксированы
в задании; результат Claude оставляет в `tasks/M1-STATUS-RESULT.md`.
Это разделение одной вехи, а не начало M2. Общий коммит M1 — после интеграции
и проверок; текущие незакоммиченные визуальные правки и ренейм сохраняются.

## 17. Итог M1

- Единственный исполнитель Git — `main/git/exec.js`: `spawn('git', argv,
  { cwd, shell: false })`, полный фактический argv с `--no-pager` и
  `-c color.ui=false`, `GIT_TERMINAL_PROMPT=0`, локальный askpass и журналирование.
- Журнал `command-log.jsonl` в `app.getPath('userData')` append-only; UI держит
  последние 2000 записей. Каждая запись содержит argv, cwd, время, длительность,
  код, stdout и stderr; поток обновляет консоль до завершения процесса.
- IPC ограничен проверенными каналами для состояния workspace, выбора каталога,
  выбора уже сохранённого репозитория и журнала. Renderer не передаёт в main
  произвольную команду или путь.
- Реальный статус — только `git status --porcelain=v2 --branch -z`; парсер
  `main/git/status-parser.js` не запускает Git и покрыт fixture self-check.
- Прогнаны `npm test`, production и dev Electron smoke на macOS arm64. M2 остаётся
  следующей вехой: подключённый репозиторий ещё показывает информационный экран,
  потому что граф, список коммитов и diff должны появиться одновременно в M2.

## 18. Итог M2

- Git-слой истории и refs (Claude Code, `tasks/M2-HISTORY.md`): `main/git/
  history-parser.js` разбирает `git log --all --topo-order -z` с собственным
  NUL-форматом (oid/parents/author/dates/subject/body) одним линейным
  проходом, без запуска Git; `main/git/history.js` грузит страницы
  (`--max-count`/`--skip`, лимит 1–500). `main/git/refs.js` разбирает `git
  for-each-ref` (у него нет `-z` — записи разделены `\n`, поля внутри записи
  NUL), даёт local/remote/tag с upstream/ahead/behind и дереференсом
  annotated-тегов на коммит, отбрасывает символическую `origin/HEAD`.
- Git-слой коммита (Codex): `main/git/commit.js` — детали коммита (`git show
  --no-patch`), список файлов (`diff-tree`/`ls-tree`), дифф файла (`show`/
  `diff` с `:(literal)` для точного пути) и сравнение диапазona
  (`diff --name-status`). Валидирует oid (hex 40/64) и путь файла (без `..`,
  без ведущего `/`, без NUL) до передачи в argv git.
- IPC (Codex): `main/history-ipc.js` добавляет `history:page/refs/commit/
  files/diff/compare`; id репозитория резолвится только по уже сохранённому
  и проверенному списку — путь из renderer недостижим напрямую.
  `preload/index.js` открывает эти каналы явными методами, без произвольного
  доступа к `ipcRenderer`.
- Граф (Codex): `renderer/src/features/graph/layout.js` — инкрементальная
  раскладка дорожек без готовой графовой библиотеки (осознанное решение §5:
  готовые графы не масштабируются на большие DAG и плохо доступны с
  клавиатуры). `CommitGraph.jsx` — виртуализация видимого окна строк от
  `scrollTop`, клавиатурная навигация (стрелки/Home/End/PageUp/PageDown).
- Сайдбар и правая панель (Codex): `HistoryWorkspace.jsx` — LOCAL/REMOTE/TAGS
  из `refs.js`, ветки с `/` группируются в папки; строка «Uncommitted
  changes» первой в дереве открывает рабочее дерево только на чтение;
  `CommitPanel.jsx` — сообщение, автор, клик по родителю, список файлов,
  дифф; Shift-клик по двум коммитам сравнивает диапазон вместо одного коммита.
- Самопроверки без запуска Git: `scripts/checks/history.mjs`, `refs.mjs`
  (парсеры и argv-билдеры), `commit.mjs` (`main/git/commit.js`), `graph.mjs`
  (раскладка дорожек на слияниях, root-коммитах, непрерывности между
  страницами и на 100k линейных коммитов, ~70 мс). Отдельный сквозной
  `scripts/history-smoke.mjs` создаёт временный настоящий Git-репозиторий
  (root, ветка, merge, 259 линейных коммитов, annotated-тег, untracked-файл)
  и гоняет через реальный Electron: пагинацию, клавиатуру, вкладки между
  репозиториями, дифф файла, рабочее дерево, отказ IPC на некорректных
  аргументах, обе темы, компактную ширину.
- Не сделано осознанно: staging, commit, stash, pull/push, любые
  history-мутирующие операции, редактор конфликтов, Undo/Redo — M3/M4.
  Правая панель показывает файлы плоским списком (`Path`), иерархия дерева
  (`Tree`) не реализована. Экран рабочего дерева — только сводка статусов.
- Версия поднята до 0.1.2 (patch — новая функциональность поверх уже
  запущенного M1, не первый стабильный релиз). Полный отчёт со сверкой
  формата `git log -z`/`for-each-ref` на реальном выводе git 2.54.0,
  расхождениями с контрактом и открытыми вопросами — `tasks/
  M2-HISTORY-RESULT.md`.
